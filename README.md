# RPG Battle — консольная игра на Dart

Консольная RPG-битва, демонстрирующая углублённое ООП в Dart:
наследование, абстрактные классы, переопределение методов и полиморфизм.
Игрок выбирает класс персонажа (Воин, Маг или Лучник) и сражается
с противником пошагово до победы одного из бойцов.

```bash

```
4. Запустить:
```bash
   dart run
```

## Что изучили

* Наследование в Dart: `class Warrior extends Character` и вызов
родительского конструктора через `super(...)`.
* Абстрактные классы и методы: `abstract class Character`,
`int attack();` без тела — контракт для наследников.
* Переопределение методов с `@override` и вызов родительской
реализации через `super.метод()` (например, в `Warrior.takeDamage`)
* Полиморфизм: функция `fight(Character attacker, Character defender)`
работает с любым наследником `Character`.
* Работа с вводом/выводом в консоли через `dart:io (stdin, stdout)`.

## Ответы на вопросы

### 1. Что такое абстрактный класс? Почему нельзя написать `Character()` напрямую?

Абстрактный класс — это класс-шаблон, который описывает общую структуру
для наследников, но не предназначен для создания экземпляров. Он может
содержать как обычные методы с реализацией (`takeDamage`, `describe`),
так и абстрактные методы без тела (`attack`, `toString`), которые
обязаны реализовать наследники.

`Character()` напрямую создать нельзя, потому что:

у абстрактного метода `attack()` нет реализации — непонятно, что
должен делать «просто персонаж»;
по смыслу «просто персонажа» не существует — в игре есть только
конкретные классы: Воин, Маг, Лучник.

### Зачем нужен super в конструкторе наследника? Что будет, если его убрать?

`super(name: name, hp: 120)` вызывает конструктор родительского класса
Character, который инициализирует поля `name`, `hp`, `maxHp` и `_random`.
Без этого вызова поля родителя останутся неинициализированными.

### В чём разница между `@override` у `attack()` и `takeDamage()` в `Warrior`?

Разница в том, что именно переопределяется:

* `attack()` в Character объявлен абстрактным — у него нет тела.
Warrior обязан его реализовать, иначе код не скомпилируется.
@override здесь подтверждает, что мы реализуем контракт родителя.
* `takeDamage()` в `Character` уже имеет реализацию — уменьшает hp
и не даёт уйти ниже нуля. Warrior переопределяет его, потому что
хочет изменить поведение: сначала уменьшить урон на `armor`,
а потом вызвать родительскую версию через `super.takeDamage(reduced)`.
`@override` здесь защищает от опечаток и документирует намерение.

### `fight(Character a, Character b)` не знает, кто реально придёт. Как называется эта концепция и где вы её уже видели во Flutter?

Это полиморфизм: переменная или параметр типа родителя может хранить
объект любого наследника, а вызов переопределённого метода
(`attacker.attack()`) диспетчеризуется в зависимости от реального типа
объекта во время выполнения.

### Что означает `_random` с нижним подчёркиванием в классе `Character`?

Нижнее подчёркивание — это модификатор приватности в Dart.
Поле `_random` доступно только внутри файла `character.dart`
(на уровне библиотеки), но недоступно из других файлов проекта.

Зачем это нужно: генератор случайных чисел — внутренняя деталь
реализации класса. Наследникам и внешнему коду не нужно знать,
как именно класс генерирует случайные числа — им достаточно
вызывать `attack()`. Приватность скрывает детали и не даёт
случайно изменить `_random` извне.
